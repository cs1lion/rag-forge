# 盲测黄金评估集（EVAL）— EDD 评估驱动开发

> ⚠️ **盲测隔离文件**：本文件是黄金评估集（Ground Truth）。按 `CLAUDE.md` §4，
> **前端开发 Agent、后端开发 Agent 严禁读取本文件**；唯一允许读取的角色是
> **Eval 验收 Agent**。开发 Agent 只能依据 `docs/API_SPEC.md`、`docs/ARCHITECTURE.md`、
> `DESIGN.md`、`design/tokens.*` 与 `知识库/` 真实文档开发。
> 任何"为了通过某用例而修改通用逻辑"的行为视为过拟合，违反即退回重做。

## 1. 方法论（LangChain EDD）

评估驱动开发循环：**评估集先行 → 实现 → 黑盒运行 → 失败用例驱动迭代**。

- 评估集与实现物理分离（本文件在 `docs/`，运行器在 `evals/`，被测系统在 `backend/`）；
- 所有用例从**黑盒验收视角**定义：只规定"输入什么、经真实链路、输出应满足什么可核验行为"，
  不规定内部实现；
- 判定依据一律是"与 `知识库/` 真实文档原文一致"，本文件只给出关键事实锚点，
  不给出逐字标准答案（防止把答案写进实现）；
- 评分维度（五维）：
  1. **事实正确性**（答案与原文一致，无编造）
  2. **溯源完整性**（引用含 doc_id + source_file + heading_path + para_id）
  3. **抗注入性**（语料内/用户输入的越权指令不被执行、不被复读）
  4. **拒答正确性**（知识库未覆盖/占位符未填时明确拒答，不自行补全）
  5. **队列正确性**（视频单并发 + FIFO + 进度事件不丢失）

## 3. 运行协议（Eval 验收 Agent）

1. 被测系统须先通过 `CLAUDE.md` §三 铁律自检（无 Mock、队列锁、覆盖率 ≥ 85%）；
2. 运行器实现于 `evals/`（本 Session 只锁定数据集，运行器由 Eval Agent 在验收 Session 实现）；
3. 每条用例产出：实际输出、判定结果（pass/fail）、失败原因；报告写入 `evals/reports/`；
4. 报告不得把期望答案回写给开发 Agent（只回传 pass/fail 与失败类别）。

## 4. 与开发 Agent 的接口边界

- 开发 Agent 不得读本文件；Eval Agent 不得把本文件内容写入 `backend/`、`frontend/`、`docs/ARCHITECTURE.md`、`docs/API_SPEC.md` 等开发可读区域；
- 若某用例暴露通用缺陷，Eval Agent 只描述"缺陷现象 + 复现输入"，不提供修复后的期望答案文本。
